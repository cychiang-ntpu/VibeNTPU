# 示範作品與評語

[← 回課程首頁](../README.md)

這裡有三份老師做的示範網站（不是真實學生作業，也不是真實服務），分別代表 [評分規準](../docs/course_plan.md) 的三個等級。看看它們的差別，就能知道自己的網站在哪個等級、下一步可以加什麼。

---

## 1. 三份作品

| 等級 | 作品 | 大約是哪個進度 | 原始碼 |
| --- | --- | --- | --- |
| LOW（基礎，及格） | 三峽學餐地圖 | 第 1 週最低完成 | [LOW/index.html](LOW/index.html) |
| MEDIUM（良好） | 三峽租屋雷達（首頁版） | 第 1 週完整完成 | [MEDIUM/index.html](MEDIUM/index.html) |
| HIGH（優秀） | 三峽租屋雷達（完整版） | 第 2 週全部完成 | [HIGH/index.html](HIGH/index.html) |

## 2. 各等級的評語

### 2.1 LOW：三峽學餐地圖

**做得好的地方：** 網頁能正常顯示，有產品名稱、一句話介紹、功能卡片和按鈕。已經達到及格。

**下一步可以加：**

- 寫出使用者遇到的困擾。可以貼給 Copilot：
  ```
  請在首頁新增一個區塊，寫出北大學生找餐廳時遇到的三個困擾，並讓每一個功能對應一個困擾。
  ```
- 讓按鈕真的有作用（目前點了沒反應）：
  ```
  請讓「立即使用」按鈕點下去後，捲動到頁面下方的加入名單區塊。
  ```
- 讓手機看起來也整齊：
  ```
  請加入手機版樣式，讓螢幕寬度小於 640px 時，卡片改成一欄排列、文字和按鈕放大。
  ```

### 2.2 MEDIUM：三峽租屋雷達（首頁版）

**做得好的地方：** 用「押金拿不回來、照片和現場不符、隔音差」三個具體困擾開場，每個功能都對應一個困擾。版面完整（導覽列、主視覺、功能、價格方案、常見問題、頁尾），手機也能看。價格分免費版和付費版，看得出怎麼賺錢。

**下一步可以加：** 目前「搶先體驗」按鈕還不能收集資料，這是第 2 週的內容。照 [第 2 週手把手實作](../lectures/wk02_1014_baas-cicd/README.md) 做，或貼給 Copilot：

```
請在頁面下方加入一個「搶先體驗」報名表單，欄位有暱稱和 Email，設定成可以被 Netlify Forms 接收，並在表單旁邊用一句話說明資料只用來通知上線消息。
```

### 2.3 HIGH：三峽租屋雷達（完整版）

**做得好的地方：** 表單能把資料送到 Netlify Forms；送出後會顯示成功或失敗訊息，並切換成會員畫面；重新整理後會員狀態還在，也可以登出。表單旁說明了資料用途。

**下一步可以加：** 網站本身已經完整，接下來是找真的使用者。把網址分享給 5 位不是同學的目標使用者，記錄他們的回饋。也可以請 Copilot 幫你寫邀請訊息：

```
我做了一個給北大學生的租屋評價網站，請幫我寫一段 80 字以內、語氣友善的邀請訊息，請租屋社團的同學試用並填寫表單。
```

提醒：LocalStorage 只是示範，真正的會員系統需要伺服器端的登入與資料庫。想了解原因，見 [深入原理（選讀）](../docs/deep_dive/README.md)。

## 3. 怎麼看這些作品

- **看程式碼：** 在 GitHub 直接點開各資料夾的 `index.html`。
- **看畫面：** 把課程 repo 複製到 VS Code，在 `samples/` 裡的 `index.html` 按右鍵，選 **Show Preview**。
- **用工具比較：** 把三份檔案分別放進 [網站自我檢核工具](../tools/vibe_check.html)，比較各 Level 的結果。
- **注意：** HIGH 的表單在自己電腦上打開時送不出去，要部署到 Netlify 才會運作。

教師若要部署本 repo 中的範例：在 Netlify 匯入時，把 **Base directory** 設為 `samples/HIGH`。三份作品的自我檢核結果由課程 CI 自動驗證（見 [course-check.yml](../.github/workflows/course-check.yml)）。
