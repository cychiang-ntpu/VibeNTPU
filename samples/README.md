# 示範作品與評語

[← 回課程首頁](../README.md)

本資料夾提供三份由授課教師製作的示範作品（非真實學生作業、非真實服務），分別對應 [分析式評分規準](../docs/course_plan.md#4-分析式評分規準) 的三個表現等級。提供不同品質等級的範例並逐項說明，目的在於讓評量標準具體可見（透明化評量），學生可據此判斷自己的作品位於哪個等級、下一步該改善什麼。

**使用建議**：先閱讀規準，再比較三份作品，嘗試自行判斷各項準則的等級，最後對照本頁評語。這比直接閱讀評語更能建立對品質的判斷力。

## 2. 逐項評語

| 評分準則 | LOW：三峽學餐地圖 | MEDIUM：三峽租屋雷達（首頁版） | HIGH：三峽租屋雷達（MVP 版） |
| --- | --- | --- | --- |
| 1. 問題與價值主張 | 基礎。有產品名稱與一句話介紹，但未說明目標使用者遇到的具體困擾，也未與現有替代方案比較。 | 良好。以「押金拿不回來」「照片與現場不符」「隔音差」三項具體困擾建立問題情境，功能與困擾一一對應。 | 良好至優秀。延續 MEDIUM 的問題陳述，並於常見問題中回應「評價真實性」這項關鍵疑慮；若能附上訪談或調查證據即達優秀。 |
| 2. 介面與使用者體驗 | 基礎。頁面可正常顯示，有標題、功能卡片與 CTA 按鈕；但 CTA 連結至 `#`，點擊後無任何作用，且未提供行動裝置專用樣式。 | 良好。具完整的形象頁（landing page）結構：導覽列、主視覺、痛點、功能、價格方案、常見問題、頁尾；以 CSS 變數統一色彩並有 `@media` 行動版調整。 | 優秀。除 MEDIUM 的結構外，送出表單後有明確的成功與失敗訊息，並於原頁面切換為會員畫面，操作回饋完整。 |
| 3. 功能實作 | 基礎。可部署並通過 Level 1，無資料收集功能。 | 良好（就第 1 週而言）。「搶先體驗」按鈕尚未收集資料，此為第 2 週的任務。 | 優秀。Netlify Forms 表單設定完整（`data-netlify`、`form-name`、honeypot 防機器人欄位）；以 `fetch` 非同步送出且格式為 urlencoded；以 LocalStorage 保存會員狀態並提供登出；存取 LocalStorage 以 `try/catch` 處理無痕模式等例外。 |
| 4. 版本控制與部署流程 | 無法由單一檔案判斷。 | 無法由單一檔案判斷。 | 無法由單一檔案判斷；學生作品應以 commit 紀錄與部署紀錄呈現。 |
| 5. 架構說明與取捨 | 頁面中無相關說明；發表時至少須說明網站託管於 Netlify。 | 價格方案呈現免費與付費兩級，反映 SaaS 常見的免費增值（freemium）模式。 | 程式碼附中文註解，說明各區塊的作用，發表時能據以解釋資料流。 |
| 6. 驗證與資料倫理 | 不適用（無資料收集）。 | 不適用（無資料收集）。 | 表單附近說明資料用途，體現告知義務；但仍須部署後以真實目標使用者驗證，示範檔案本身不含驗證數據。 |

## 3. 各等級的改進方向

### 3.1 LOW → MEDIUM

LOW 等級已達及格標準。若要提升，可依下列方向請 Copilot 修改，並於修改後自行檢查結果是否符合預期：

1. **補充問題陳述**：「請新增一個區塊，具體說明北大學生找餐廳時遇到的三個困擾，並讓每項功能對應一個困擾。」
2. **呈現商業模式**：「請將價格區改為免費版與進階版的比較卡片，列出兩者差異。」
3. **行動版樣式**：「請加入 `@media (max-width: 640px)` 的行動版樣式。」
4. **修正無效連結**：「請讓『立即使用』按鈕捲動到頁面下方的加入名單區塊。」

### 3.2 MEDIUM → HIGH

1. 依 [第 2 週教材](../lectures/wk02_1014_baas-cicd/README.md) 加入 Netlify Forms 表單，並開啟 Form detection。
2. 以 `fetch` 非同步送出，並以 LocalStorage 呈現會員狀態。
3. 在表單附近說明資料用途，僅收集必要欄位。

### 3.3 HIGH 之後

1. 將網址提供給非同學的目標使用者，蒐集真實的轉換數據與回饋。
2. LocalStorage 僅為示範；真正的會員系統需要伺服器端身分驗證與資料庫，例如 [Supabase](https://supabase.com/) 等 BaaS 服務。
3. 若有評價內容，需考量內容審核、誹謗風險與個資保護等營運與法律議題。

## 4. 如何檢視示範作品

- **檢視原始碼**：於 GitHub 直接開啟各 `index.html`。
- **檢視畫面**：以 VS Code clone 課程 repo（`https://github.com/cychiang-ntpu/VibeNTPU`），於 `samples/` 中的 `index.html` 按右鍵選擇 Show Preview；或於 GitHub 下載原始檔後以瀏覽器開啟。
- **注意**：HIGH 的表單若以 `file:///` 在本機開啟，送出必定失敗，因為 Netlify Forms 須部署至 Netlify 後才會運作。
- **以自我檢核工具比較**：將三份檔案分別載入 [網站自我檢核工具](../tools/vibe_check.html)，比較各 Level 的結果差異。

## 5. 部署 HIGH 作品進行測試

1. 下載 `HIGH/index.html`。
2. 依 [GitHub 與 Netlify 部署教學](../docs/tutorials/github_netlify_deploy.md) 建立新 repo 並部署。
3. 依 [Netlify Forms 教學](../docs/tutorials/netlify_forms.md) 開啟 Form detection 並重新部署。

教師若要直接部署本 repo 中的範例，於 Netlify 匯入時將 Base directory 設為 `samples/HIGH` 即可。
