# 課程規劃：學習目標、進度與評量

[← 回課程首頁](../README.md)

這份文件說明：上完課你應該會什麼、每週做什麼、怎麼評分、使用 AI 的規則，以及課堂規範。評分標準在開課前就公開，讓你事先知道什麼是好的成果。

---

## 1. 學習目標

完成本單元後，你應該能：

| 編號 | 你會做到 | 怎麼看出來 | 檢核點 |
| --- | --- | --- | --- |
| LO1 | 看著社群媒體架構圖，說出一次「按讚」經過哪些服務 | 架構小測驗答對 80% 以上 | 1 |
| LO2 | 說出前端、版本控制、雲端託管、後端服務（BaaS）各負責什麼 | 小測驗；發表時的架構說明 | 1、7 |
| LO3 | 用 VS Code 和 GitHub Copilot 做出並修改自己題目的網頁 | 能預覽的 `index.html`；AI 使用紀錄 | 2 |
| LO4 | 用 Git 完成複製、提交、同步，並用 Netlify 發布網站 | GitHub 上的提交紀錄；Netlify 網址 | 2、3 |
| LO5 | 用 Netlify Forms 收集表單資料，並說明資料去了哪裡、要如何保護個資 | 後台收件紀錄（截圖遮蔽個資）；自我檢核 Level 2 | 4 |
| LO6 | 說出 LocalStorage 和伺服器資料庫的差別（安全性、會不會消失、適合用在哪） | 自我檢核 Level 3；學習單比較題 | 5 |
| LO7 | 透過實際修改，說明「自動部署（CI/CD）」讓更新變快的好處 | Netlify 部署紀錄與對應的提交；反思 | 6 |
| LO8 | 用「問題、解方、架構、數據」完成 1 分鐘產品發表 | 發表表現（依第 4 節規準） | 7 |

## 3. 評量方式與權重

| 項目 | 比重 | 看什麼 | 從哪裡看 |
| --- | --- | --- | --- |
| 第 1 週成果 | 20% | 網站已上線（10%）；內容符合題目、手機可閱讀（10%） | Netlify 網址；自我檢核 Level 1 |
| 第 2 週成果 | 30% | 表單能收件（10%）；會員畫面（10%）；至少一次自動部署紀錄（10%） | Netlify 後台；自我檢核 Level 2、3；GitHub 提交紀錄 |
| 學習歷程檔案與反思 | 10% | 反思寫得具體；有 AI 使用紀錄 | 你 repo 中的 [學習歷程檔案](../templates/portfolio_README.md) |
| 市場驗證 | 10% | 有非同學的目標使用者回應，並寫出你的觀察 | 學習歷程檔案的市場紀錄 |
| MVP 發表 | 30% | 問題與解方、架構說明、現場展示、驗證證據 | 課堂發表（依第 4 節規準） |

說明：

1. 反思不評文筆，只看是否具體：寫出發生什麼事、怎麼解決、還有哪裡不懂，就能拿滿分。
2. 市場驗證看方法與觀察，不比名單數量。
3. 檢核點只用來確認進度，不另外計分。

## 4. 分析式評分規準

每一項分三個等級，對應 [示範作品](../samples/README.md) 的 LOW、MEDIUM、HIGH。「基礎」就是及格。

| 評分項目 | 基礎（LOW，及格） | 良好（MEDIUM） | 優秀（HIGH） |
| --- | --- | --- | --- |
| 1. 問題與價值 | 有產品名稱和一句話介紹，但使用者和問題寫得籠統 | 清楚寫出目標使用者和他們的具體困擾，功能對應到困擾 | 問題有證據支持（訪談、觀察或公開資料），並說明和現有做法有什麼不同 |
| 2. 介面與使用體驗 | 頁面能正常顯示，有標題、說明和行動按鈕（例如「立即加入」） | 版面完整（導覽、主視覺、功能、價格、常見問題），手機可正常閱讀 | 視覺風格一致；送出後有成功或失敗訊息；字夠大、顏色對比清楚、表單有標籤 |
| 3. 功能 | 網站已在 Netlify 上線（Level 1） | 表單資料能送到 Netlify Forms 後台（Level 2） | 送出表單後出現會員畫面，有登出和錯誤處理（Level 3） |
| 4. 版本控制與部署 | repo 存在且有第一次提交 | 有多次提交，訊息看得出改了什麼；Netlify 已連接 GitHub | 提交訊息清楚說明每次修改的目的；能指出某次提交對應的自動部署紀錄 |
| 5. 架構說明 | 能說出網站放在 Netlify | 能正確說明四個部分各負責什麼、資料怎麼流動 | 能說明為什麼這樣選、有什麼限制（成本、速度、安全），以及下一步怎麼改進 |
| 6. 驗證與資料倫理 | 表單能用，但只有同學的測試資料 | 有非同學的目標使用者回應，並寫出觀察 | 用數據（例如填寫率）支持結論；告知資料用途；發表時遮蔽個資 |

## 5. AI 使用規範

歡迎使用 AI，但你要為結果負責。

### 5.1 揭露

- 在學習歷程檔案的「AI 使用紀錄」寫下：用了什麼工具、做什麼、主要提示詞、你自己改了什麼。
- 發表中若有 AI 產生的文案、圖片或數據，請說明。

### 5.2 檢查

- AI 產生的網頁一定要實際預覽和測試。發表時要能說明主要區塊在做什麼；看不懂的地方可以請 Copilot 的 Ask 模式解釋。
- AI 說的數字、市場規模、法規，要找到原始來源；查不到就不能拿來當證據。
- AI 可能編造不存在的網址或工具，也可能寫出不安全的程式，使用前要檢查。

### 5.3 隱私

- 不要把別人的個資（姓名、Email、電話、表單內容）貼給 AI。
- 不要把密碼、驗證碼、存取權杖（token）貼給 AI 或寫進程式碼。
- 網站收集資料時，要在表單旁說明用途；發表截圖要遮蔽個資（參考《個人資料保護法》）。

### 5.4 學術誠信

- Git 的提交（Commit）和同步（Sync）請自己在「原始檔控制」面板操作，不要叫 Copilot 代做，這是本課要學會的技能。
- 反思和市場觀察要自己寫，不能由 AI 代寫。
- 展示可以用假資料，但要標明；發表中的驗證數據必須是真的。

## 6. 課堂規範

| 規範 | 怎麼做 |
| --- | --- |
| 兩人一組 | 一人操作電腦（駕駛），一人看步驟並檢查（導航員）；每段實作交換角色。兩人都要完成自己的網站 |
| 回饋卡 | 完成目前步驟貼綠色，需要幫忙貼紅色，助教會主動過來 |
| 15 分鐘原則 | 同一問題試了 15 分鐘沒進展就求助 |
| 求助順序 | [疑難排解手冊](tutorials/error_guide.md) → Copilot Ask 模式（附錯誤訊息）→ 同學 → 助教或 [求助單](https://github.com/cychiang-ntpu/VibeNTPU/issues/new?template=help_request.yml) |
| 友善回饋 | 作品巡禮用「我喜歡／我希望／如果」三句話給具體回饋 |
| 保護個資 | 投影和截圖前，確認畫面沒有別人的個資 |
