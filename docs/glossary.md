## 1. 商業

| 名詞 | 一句話說明 |
| --- | --- |
| **SaaS**（軟體即服務） | 不用安裝、打開瀏覽器就能用、按月或按年付費的軟體，例如 Canva、Notion。類比：美食街的店家，不用自己蓋商場。 |
| **訂閱制** | 每個月或每年固定付費，持續使用服務。 |
| **Freemium**（免費增值） | 基本功能免費，想要更多功能或額度才付費，例如 Copilot Free 與 Pro。 |
| **MVP**（最小可行產品） | 用最少的力氣做出來、足以測試「有沒有人要」的第一版產品。 |
| **精實創業**（Lean Startup） | 先做小東西給使用者試，看反應再調整，而不是一開始就做很大。 |
| **形象首頁**（Landing page） | 介紹產品、請訪客留下聯絡方式的單一網頁，是第 1 週的作品。 |
| **價值主張** | 用一句話說清楚：你的產品幫誰解決什麼問題。 |
| **CTA**（行動呼籲） | 請訪客採取行動的按鈕，例如「加入早鳥名單」。 |
| **候補名單**（Waitlist） | 產品上線前，先收集有興趣的人的聯絡方式。 |
| **轉換率** | 來看網頁的人之中，真的按下按鈕或填表的比例。 |
| **MRR**（月經常性收入） | 每個月固定會收到的訂閱收入總和。 |
| **流失率**（Churn） | 一段時間內取消訂閱的客戶比例。 |

## 2. 網站怎麼組成

| 名詞 | 一句話說明 |
| --- | --- |
| **前端** | 使用者在瀏覽器上看到、可以點的部分。類比：店面。 |
| **後端** | 在伺服器上處理資料、使用者看不到的部分。類比：廚房。 |
| **伺服器** | 24 小時開著、負責把網頁送給訪客的電腦。 |
| **資料庫** | 在伺服器上長期存放資料（例如會員名單）的地方。 |
| **API** | 兩個軟體之間約好的溝通方式。類比：餐廳的點餐單。 |
| **BaaS**（後端即服務） | 別人做好的後端功能，拿來直接用，例如本課程的 Netlify Forms。 |
| **PaaS**（平台即服務） | 你只要交出檔案，伺服器由平台負責，例如 Netlify。 |

## 3. 網頁

| 名詞 | 一句話說明 |
| --- | --- |
| **HTML** | 決定網頁上「有什麼東西」（標題、段落、表單）的語言。 |
| **CSS** | 決定網頁「長什麼樣子」（顏色、字型、排版）的語言。 |
| **JavaScript** | 決定網頁「會做什麼」（按下按鈕後切換畫面）的程式語言。 |
| **`index.html`** | 網站首頁的檔名，全部小寫，網址沒有指定檔名時就打開它。 |
| **靜態網站** | 伺服器只負責把做好的檔案送出去的網站，本課程的網站就是這種。 |
| **RWD**（響應式網頁設計） | 讓同一個網頁在手機和電腦上都能好好顯示的做法。 |
| **Viewport** | 告訴手機「照手機寬度顯示」的設定，沒有它手機上字會很小。 |
| **UTF-8** | 讓中文正常顯示的文字編碼，沒設定時中文可能變亂碼。 |
| **HTTPS** | 加密的網址連線，網址列會出現鎖頭圖示。 |
| **LocalStorage** | 瀏覽器裡的小儲物櫃，網站可以在這裡記住你，但只存在這台裝置的這個瀏覽器。 |
| **DevTools**（開發者工具） | 瀏覽器內建的檢查工具，按 `F12` 打開，可看錯誤訊息。 |

## 4. Git 與 GitHub

| 名詞 | 一句話說明 |
| --- | --- |
| **Git** | 裝在電腦裡、記錄每一次修改的工具。 |
| **GitHub** | 放 Git 專案的雲端網站，可以在網頁上看檔案和修改紀錄。 |
| **repo**（儲存庫） | 放在 GitHub 上的專案資料夾，會記住每一次修改。 |
| **複製（Clone）** | 把 GitHub 上的 repo 下載到電腦，並保持連線。 |
| **提交（Commit）** | 把目前的檔案存成一個版本。類比：遊戲存檔點。 |
| **同步變更（Sync Changes）** | 把電腦上的存檔點上傳到 GitHub，同時下載 GitHub 上的新版本。 |
| **捨棄變更（Discard Changes）** | 把還沒提交的修改丟掉，回到上一個存檔點。 |
| **原始檔控制（Source Control）** | VS Code 左側樹枝分岔的圖示，提交與同步變更都在這裡按。 |
| **`main`** | repo 預設的主線名稱，Netlify 會從這裡拿檔案部署。 |

## 5. 部署

| 名詞 | 一句話說明 |
| --- | --- |
| **部署**（Deploy） | 把網頁放到網路上，讓別人也能打開。 |
| **託管**（Hosting） | 由服務商提供伺服器，讓你的網站一直在線上。 |
| **Netlify** | 本課程用的網站託管平台，會從 GitHub 拿檔案變成網站。 |
| **持續部署**（CD） | 每次同步變更後，網站自動更新，不用手動上傳。 |
| **GitHub Actions** | GitHub 內建的自動化功能，本課程選做任務用它自動檢查網頁。 |
| **回復**（Rollback） | 把網站切回之前的某一版，在 Netlify 的 Deploys 頁面操作。 |

## 6. AI 與工具

| 名詞 | 一句話說明 |
| --- | --- |
| **VS Code** | 編輯網頁的免費軟體。類比：廚房的工作檯。 |
| **終端機** | 用打字方式下指令給電腦的地方，在 VS Code 中點選 **檢視 > 終端機** 打開。 |
| **延伸模組**（Extension） | 幫 VS Code 加功能的外掛，例如 Live Preview。 |
| **GitHub Copilot** | VS Code 裡的 AI 助理，你用中文描述，它幫你寫程式碼。 |
| **提示詞**（Prompt） | 你給 AI 的指示，寫得越具體，結果越接近你要的。 |
| **Ask 模式** | Copilot 只回答問題、不改檔案的模式。 |
| **Agent 模式** | Copilot 會直接建立或修改檔案的模式，改完要自己檢查再按保留。 |
| **幻覺**（Hallucination） | AI 講得很有自信、但其實是錯的內容。 |
| **Vibe Coding** | 用自然語言描述需求、主要由 AI 寫程式，人負責檢查結果的做法。 |
| **雙重驗證**（2FA） | 登入時除了密碼，還要輸入手機 App 產生的驗證碼。 |

## 7. 進階名詞（選讀）

以下名詞課堂不要求，想深入了解時可參考。詳細說明見 [Git、Copilot 與部署機制（選讀）](deep_dive/git_and_copilot.md) 與 [選讀資料夾](deep_dive/README.md)。

### 7.1 商業與架構

| 名詞 | 一句話說明 |
| --- | --- |
| **CAC／LTV** | 取得一位客戶的成本，以及一位客戶一生能帶來的收入；LTV 要明顯大於 CAC 才賺錢。 |
| **A/B 測試** | 把訪客分兩組看不同版本，比較哪一版效果好。 |
| **IaaS**（基礎設施即服務） | 向雲端租用虛擬電腦，作業系統以上都要自己管，例如 AWS EC2。 |
| **無伺服器**（Serverless） | 開發者不用管伺服器，平台依使用量自動分配資源並計費。 |
| **CDN**（內容傳遞網路） | 把網站複製到世界各地的伺服器，讓訪客從最近的地方讀取。 |
| **快取**（Cache） | 把常用的資料暫存在比較快的地方，代價是可能不是最新版。 |
| **負載平衡** | 把大量訪客分配到多台伺服器，避免一台被擠爆。 |
| **訊息佇列** | 讓系統把工作排隊、依序處理，平緩流量高峰。 |
| **微服務** | 把大系統拆成很多各自獨立的小服務。 |
| **推播通知** | 由伺服器主動送到手機上的通知。 |
| **可擴展性** | 使用者變多時，系統能透過加資源維持速度的能力。 |

### 7.2 網頁

| 名詞 | 一句話說明 |
| --- | --- |
| **HTTP** | 瀏覽器和伺服器之間傳送網頁的規則；HTTPS 是加密版。 |
| **DNS** | 把網址（例如 `example.com`）翻譯成伺服器位址的系統。類比：電話簿。 |
| **AJAX／fetch** | 不重新整理整頁，就在背景送出或取得資料的技術。 |
| **Honeypot**（誘捕欄位） | 表單中人看不到、但機器人會填的欄位，用來擋垃圾訊息。 |

### 7.3 Git

| 名詞 | 一句話說明 |
| --- | --- |
| **工作目錄**（Working tree） | 你在電腦上看到、正在編輯的專案檔案。 |
| **暫存區**（Staging area） | 挑選「這次要提交哪些修改」的地方，VS Code 中是檔案旁的 ＋。 |
| **Push／Pull／Fetch** | 上傳到 GitHub／從 GitHub 下載並合併／只下載不合併；同步變更等於先 Pull 再 Push。 |
| **分支**（Branch） | 從主線分出去、可以獨立修改的另一條線，本課程只用 `main`。 |
| **origin** | 電腦上的 repo 對「GitHub 上那一份」的預設稱呼。 |
| **合併衝突**（Merge conflict） | 兩邊改了同一段內容，Git 不知道該留哪一個，需要人決定。 |
| **Pull Request**（PR） | 在 GitHub 上請別人審查並合併你的修改。 |
| **.gitignore** | 列出 Git 不要記錄哪些檔案的設定檔。 |
| **Hash**（雜湊值） | 每個 commit 的獨特編號，例如 `3f9a2c1`。 |

### 7.4 部署與 AI

| 名詞 | 一句話說明 |
| --- | --- |
| **建置**（Build） | 把原始碼加工成可以上線的檔案；本課程的純 HTML 不需要。 |
| **發布目錄**（Publish directory） | Netlify 要把 repo 中哪個資料夾當成網站；本課程留空，代表最外層。 |
| **Webhook** | 事件發生時，一個系統主動通知另一個系統；GitHub 用它通知 Netlify 有新版本。 |
| **OAuth** | 讓你授權某個 App 使用你的帳號、但不必交出密碼的登入方式。 |
| **CI**（持續整合） | 每次上傳就自動跑檢查，盡早發現問題。 |
| **原子化部署** | 新版本全部上傳完才一次切換，訪客不會看到一半新一半舊的網站。 |
| **TLS 憑證** | 讓網站能使用 HTTPS 的數位證明，Netlify 會自動申請。 |
| **大型語言模型**（LLM） | Copilot 背後的 AI，會依前文預測最可能接下來的文字。 |
| **上下文**（Context） | AI 回答時能參考的所有資訊，包括你的提示詞與打開的檔案。 |
| **配對程式設計** | 兩人一起寫程式，一人操作、一人檢查，定期交換角色。 |
