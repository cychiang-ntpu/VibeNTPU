# 以 GitHub Actions 自動檢核網站

> **性質**：延伸任務（選做）：GitHub Actions 自動檢核
> **先備條件**：已完成檢核點 3（repo 中已有 `index.html` 並成功部署）
> **預估時間**：約 15 分鐘
> **做完你會得到**：每次同步變更後，GitHub 會自動用課程標準檢查你的網頁，並在 repo 上顯示綠色勾號（通過）或紅色叉號（未通過）。

[← 回教學目錄](README.md)

---

## 先懂一件事

**GitHub Actions** 是 GitHub 內建的自動化功能：你放一個設定檔到 repo 裡，之後每次上傳，GitHub 就會自動幫你跑一遍檢查。它做的事和 [網站自我檢核工具](../../tools/vibe_check.html) 一樣，只是不用你自己手動打開。檢查沒通過**不會**阻止網站更新，只是提醒你還有地方要改。

想了解原理（工作流程、觸發條件、執行器等名詞）：見 [Git、Copilot 與部署機制（選讀）](../deep_dive/git_and_copilot.md)。

---

## 步驟 1：複製設定檔內容（約 2 分鐘）

1. 打開課程 repo 的 [tools/ci/vibe-check.yml](../../tools/ci/vibe-check.yml)（在 GitHub 網頁上開啟）。
2. 在檔案內容右上角，找到兩個方框重疊的 **Copy raw file** 圖示，按一下。

**完成後你應該看到：** 圖示短暫變成打勾，代表全文已複製。

**如果不一樣：** 找不到圖示 → 按 **Raw** 按鈕，在打開的純文字頁面按 `Ctrl+A` 全選、`Ctrl+C` 複製（Mac：`⌘A`、`⌘C`）。

---

## 步驟 2：在你的 repo 建立設定檔（約 3 分鐘）

1. 在 VS Code 開啟**你自己的** repo 資料夾（例如 `rent-radar`）。
2. 在左側檔案總管，把滑鼠移到資料夾名稱那一列，按 **新增檔案（New File）** 圖示（一張紙加上 ＋）。
3. 輸入下面這一行（要完全一樣），按 Enter：
   ```
   .github/workflows/vibe-check.yml
   ```
   注意：最前面有一個半形句點 `.`；`workflows` 結尾有 `s`。輸入斜線時，VS Code 會自動建立資料夾。
4. 在打開的空白檔案中按 `Ctrl+V`（Mac：`⌘V`）貼上。
5. 按 `Ctrl+S`（Mac：`⌘S`）存檔。

**完成後你應該看到：** 左側出現 `.github` 資料夾，裡面有 `workflows` 資料夾，裡面有 `vibe-check.yml`。

**如果不一樣：** 檔案建在錯的位置 → 在該檔案上按右鍵選 **刪除**，重做第 2 項。貼上後不要修改任何空格或縮排。

---

## 步驟 3：提交並同步變更（約 2 分鐘）

1. 點選左側 **原始檔控制** 圖示（樹枝分岔的圖示）。
2. 在訊息框輸入 `新增 GitHub Actions 自動檢核`。
3. 按 **提交（Commit）**。
4. 按 **同步變更（Sync Changes）**。

**完成後你應該看到：** 同步變更按鈕消失。

**如果不一樣：** 見 [疑難排解手冊](error_guide.md) Q7、Q8。

---

## 步驟 4：看檢查結果（約 3 分鐘）

1. 打開瀏覽器中你的 GitHub repo 頁面。
2. 點上方的 **Actions** 分頁。
3. 會看到一筆紀錄，前面有黃色圓點（執行中）。等 30 秒到 1 分鐘。
4. 圓點變成綠色勾號（通過）或紅色叉號（未通過）後，點進那一筆紀錄。
5. 往下捲，閱讀 **Summary（摘要）** 區的報告。

**完成後你應該看到：** 報告列出每一個檢查項目與結果。

**如果不一樣：** Actions 分頁完全沒有紀錄 → 在 GitHub 網頁確認檔案位置是 `.github/workflows/vibe-check.yml`（開頭有句點、`workflows` 有 s），並確認已同步變更。

---

## 步驟 5：未通過時修正（每次約 5 分鐘）

紅色叉號代表檢查機制正常運作、找到了還沒做到的項目，不代表你操作錯誤。

1. 在 Summary 報告中，找到標示未通過的項目。
2. 每個項目下方都有一段可以直接交給 AI 的提示詞，把它複製起來。
3. 回到 VS Code，打開 Copilot 聊天面板（Agent 模式），貼上提示詞送出。
4. 檢查預覽後，按 **保留（Keep）**。
5. 提交、同步變更。
6. 回到 GitHub 的 Actions 分頁，看最新一筆結果。

**完成後你應該看到：** 最新一筆紀錄變成綠色勾號。

**如果不一樣：** 顯示找不到 `index.html` → 確認檔案在 repo 最外層，且檔名全部小寫。

---

## 步驟 6：課程進度往前時，調高檢核等級（約 2 分鐘）

設定檔中的 `LEVEL` 決定檢查範圍。完成新的功能後，把數字調高。

1. 在 VS Code 打開 `.github/workflows/vibe-check.yml`。
2. 找到這兩行：
   ```yaml
   env:
     LEVEL: "1"
   ```
3. 只把引號中的數字改掉（引號與前面的空格都不要動）：

   | 改成 | 什麼時候改 | 會多檢查什麼 |
   | --- | --- | --- |
   | `"1"` | 第 1 週，檢核點 3 | 產品首頁的基本要素 |
   | `"2"` | 第 2 週，完成表單（檢核點 4） | Netlify Forms 表單 |
   | `"3"` | 第 2 週，完成會員儀表板（檢核點 5） | LocalStorage 會員狀態與在原頁面送出表單 |

4. 按 `Ctrl+S` 存檔。
5. 提交、同步變更。

**完成後你應該看到：** Actions 分頁出現新的一筆紀錄，報告中列出新等級的檢查項目。

**如果不一樣：** 仍以舊等級檢查 → 確認已存檔、提交並同步變更，並點開的是「最新」那一筆。

---

## 問題排除

| 你看到的狀況 | 怎麼做 |
| --- | --- |
| Actions 分頁沒有任何紀錄 | 確認檔案路徑是 `.github/workflows/vibe-check.yml`，並已同步變更 |
| 顯示 YAML 語法錯誤 | 刪除檔案全部內容，重新複製範本全文貼上，不要改縮排 |
| 「下載檢核腳本」步驟失敗 | 在該筆紀錄頁面按 **Re-run jobs** 重新執行 |
| 報告顯示找不到 `index.html` | 把檔案移到 repo 最外層，檔名改成全小寫 |
| 改了 LEVEL 還是舊的結果 | 確認已存檔、提交、同步變更，並查看最新一筆 |
