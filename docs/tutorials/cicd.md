# CI/CD 步驟教學：觀察自動部署與回到上一版

[回第 2 週手把手實作](../../lectures/wk02_1014_baas-cicd/README.md)

CI/CD（持續整合／持續部署）是「程式碼一更新，系統就自動把新版放上網站」的做法。第 1 週你用 **Import from Git** 建立 Netlify 網站時，就已經把它設定好了：每次你在 VS Code 按 **同步變更（Sync Changes）**，GitHub 會通知 Netlify，Netlify 自動部署新版。每次部署都會留下一筆紀錄，所以出錯時可以幾秒內回到上一版。本頁帶你觀察這個過程、查看部署紀錄，並練習回到上一版。

想了解原理：見 [表單、儲存與 CI/CD 深入閱讀](../deep_dive/forms_storage_cicd.md)（選讀）。

---

## 步驟 1：記下目前的樣子（約 1 分鐘）

1. 用手機打開你的 `https://…netlify.app` 網址。
2. 記下主按鈕的顏色和文字。

## 步驟 2：做一個一眼看得出來的修改（約 3 分鐘）

1. 打開 [第 2 週提示詞](../../lectures/wk02_1014_baas-cicd/prompts.md)，複製「提示詞 3」其中一個灰色框。
2. 在 VS Code 的 Copilot Chat（Agent 模式）貼上並送出。
3. 按下 **保留（Keep）**。
4. 按 `Ctrl+S`（Mac：`⌘S`）存檔。

**完成後你應該看到：** `index.html` 中按鈕的顏色或文字被改掉了。

## 步驟 3：提交並同步（約 2 分鐘）

1. 點選 VS Code 左側 **原始檔控制（Source Control）** 圖示（形狀像樹枝分岔，快捷鍵 `Ctrl+Shift+G`，Mac：`⌃⇧G`）。
2. 在訊息欄輸入 `改按鈕顏色`。
3. 按下 **提交（Commit）**。
4. 按下 **同步變更（Sync Changes）**。

**完成後你應該看到：** 原始檔控制面板變回空的。

## 步驟 4：不碰 Netlify，直接看手機（約 1 分鐘）

1. 不要打開 Netlify。
2. 等大約 30 秒。
3. 在手機上重新整理網頁。

**完成後你應該看到：** 按鈕已經變成新的樣子。這就是檢核點 6。

**如果不一樣：** 還是舊的 → 再等 30 秒，往下拉重新整理，或用無痕視窗打開。

## 步驟 5：查看部署紀錄（約 2 分鐘）

1. 打開 <https://app.netlify.com/>，點選你的網站。
2. 點選左側選單的 **Deploys**。
3. 點選最上面那一筆。

**完成後你應該看到：** 這一筆顯示你的提交訊息 `改按鈕顏色`、狀態 **Published**，以及部署過程的紀錄（Deploy log）。往下捲，可以看到之前每一次同步留下的紀錄。

**如果不一樣：** 狀態是 **Failed** → 點進去看紅字，並見 [疑難排解手冊](error_guide.md) Q11–Q13。

## 步驟 6（選做）：回到上一版（約 3 分鐘）

1. 在 **Deploys** 清單中，點選下面一筆較舊、狀態為 **Published** 的部署。
2. 按下 **Publish deploy**。
3. 在確認視窗中再按一次確認。
4. 用手機重新整理網站。

**完成後你應該看到：** 網站在幾秒內回到舊的樣子，不需要重新部署。

## 步驟 7（選做）：換回最新版（約 2 分鐘）

回到上一版只改變網站，GitHub 上的程式碼仍是新版。練習完請換回來，以免之後搞混。

1. 在 **Deploys** 清單中，點選最新那一筆。
2. 按下 **Publish deploy**。
3. 用手機重新整理網站。

**完成後你應該看到：** 網站回到新版。下一次你同步新修改時，Netlify 也會自動部署最新的程式碼。

## 其他查看修改歷史的地方

- GitHub 網頁上你的 repo 頁面 → **Commits**。
- VS Code 原始檔控制面板下方的 **圖表（Graph）**。
