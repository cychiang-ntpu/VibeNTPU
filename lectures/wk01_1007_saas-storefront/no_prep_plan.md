# 第 1 週調整版授課計畫：學生未做課前準備（教師用）

適用情境：學生沒有在課前完成 [課前準備清單](../../docs/tutorials/before_class.md)（檢核點 0），帳號申請與軟體安裝都必須在課堂上完成。

[回第 1 週手把手實作](README.md)　｜　[學生課後作業](homework.md)

---

## 1. 調整原則

課前準備（註冊 GitHub、安裝 VS Code 與 Git、登入、啟用 Copilot）在課堂上約需 40 分鐘，因此原本 2 小時的內容放不下。調整方式：

1. **課堂只做「必須有人在旁邊才做得完」的事**：安裝、登入、建立 repo、第一次請 Copilot 做網頁、第一次提交與同步。這些步驟最容易卡住，需要教師與助教現場協助。
2. **能自己照文件完成的事改成課後作業**：互動網頁操作與小測驗、Copilot 修改網頁、Netlify 上線（若課堂來不及）、雙重驗證、學生方案申請、學習歷程檔案。
3. **今天的最低完成線**：學生的 `index.html` 已經**提交並同步到 GitHub**。只要做到這一步，其餘都能在家照 [課後作業](homework.md) 完成。

## 3. 環境安裝 40 分鐘的帶法

| 分鐘 | 學生要做的事 | 對應 [課前準備清單](../../docs/tutorials/before_class.md) | 備註 |
| --- | --- | --- | --- |
| 0–10 | 申請 GitHub 帳號、收驗證信 | 步驟 1-1 | 若 GitHub 當下要求設定雙重驗證就照做（步驟 1-2 至 1-4）；若沒有要求，**留到課後作業**。全班同時註冊時，GitHub 可能要求較多次人機驗證，屬正常現象 |
| 0–15（同時） | 安裝 VS Code 與 Git | 步驟 3、4 | 開場時已開始下載，此時應已下載完成。Windows 安裝 Git 全部按預設值 |
| 15–20 | 設定 Git 使用者名稱與 Email | 步驟 5 | 教師投影兩行指令，學生複製貼上 |
| 20–30 | VS Code 登入 GitHub、啟用 Copilot Free | 步驟 6、7 | 最常卡在瀏覽器授權後沒有跳回 VS Code：請學生回到 VS Code 再點一次左下角帳戶圖示 |
| 30–40 | 緩衝時間 | — | 已完成的人當小助教，協助同組或隔壁同學 |

**省略或延後的項目：**

- 步驟 2（GitHub 學生方案）：審核需數天，列為課後作業第一項，請學生今天回家就申請。
- 步驟 8（Live Preview）：課堂上改用「在檔案總管中雙擊 `index.html`」預覽，不必安裝。
- 步驟 9（Hello NTPU 練習）：直接跳到 README 步驟 13–17 做正式網頁，不另做練習。
- 步驟 10（Netlify 註冊）：移到 1:35 之後，完成提交與同步的人再做。

## 4. 課堂上的應變

| 狀況 | 處理方式 |
| --- | --- |
| 學生沒帶筆電，或筆電無法安裝軟體 | 與同組同學共用一台電腦當導航員；帳號註冊（GitHub、Netlify）可用手機完成。軟體安裝與後續步驟列入課後作業 A1 |
| 到 1:35 仍有學生沒完成 clone | 請該生先停在原處，課後依 [homework.md](homework.md) 的 A1 從斷點接續。不要為了等少數人延後全班進度 |
| Copilot 啟用失敗或沒有回應 | 先用 [提示詞](prompts.md) 中「沒有 Copilot 時的備案」（網頁版 AI＋貼上存檔），讓學生至少完成 `index.html` 與提交、同步 |
| Netlify 來不及做 | 正常。課後作業 A2 有完整步驟，約 15 分鐘 |

## 5. 對第 2 週（10/14）的影響

1. **10/13（二）晚上檢查進度**：請學生在課程群組貼出網站網址（課後作業 A6）。沒有網址的同學，就是 10/14 需要優先協助的人。
2. **10/14 開頭加 10 分鐘補做時間**：未完成第 1 週的同學由助教協助完成 Netlify 上線；已完成的同學利用這 10 分鐘做 [第 2 週學習單](../wk02_1014_baas-cicd/worksheet.md) 第 1、2 題。
3. 為了挪出這 10 分鐘，第 2 週 Part 1（資料去哪了）由 15 分鐘縮為 5 分鐘：教師投影 [data_flow.html](../wk02_1014_baas-cicd/slides/data_flow.html) 示範一次即可，學生已在課後作業 C 預先操作過。
