# 第 1 週調整版授課計畫：學生未做課前準備（教師用）

適用情境：學生沒有在課前完成 [課前準備清單](../../docs/tutorials/before_class.md)（檢核點 0），帳號申請與軟體安裝都必須在課堂上完成。

**本學期實際情況：課堂在電腦教室的 Windows 桌機上進行，學生回家可能用 macOS。** 這帶來三個差異，請先看第 0 節。

## 0. 電腦教室桌機的三件事

1. **開課前確認桌機已有 VS Code 與 Git。** 公用電腦通常不允許學生安裝軟體。請提早到教室，在一台桌機上打開 VS Code，終端機輸入 `git --version`。
   - 兩者都有：第 3 節的「安裝」時段縮短為 15 分鐘（只做帳號、`git config`、登入、Copilot），多出的時間給 Netlify 上線。
   - 缺其中一樣：聯絡電腦教室管理員；若無法安裝，改用「網頁版備案」（下方第 4 節），今天的目標改為「GitHub 網頁上有 `index.html`」。
2. **桌機重開機可能還原。** 學生在課堂電腦上做的一切，下課後都可能消失。所以今天的底線「提交並同步到 GitHub」不是可選項，而是**唯一能把成果帶回家的方法**。請在 1:35 之前反覆提醒。
3. **下課前登出。** GitHub、Netlify、VS Code 的登入狀態會留在公用電腦上。下課前 3 分鐘，請全班依 [Windows 與 macOS 差異對照](../../docs/tutorials/windows_vs_macos.md) 第 5 節登出。

回家用 macOS 的學生：請他們看 [Windows 與 macOS 差異對照](../../docs/tutorials/windows_vs_macos.md)，第 4 節說明如何在自己的電腦上 clone 回今天的成果。

## 1. 調整原則

課前準備（註冊 GitHub、安裝 VS Code 與 Git、登入、啟用 Copilot）在課堂上約需 40 分鐘，因此原本 2 小時的內容放不下。調整方式：

1. **課堂只做「必須有人在旁邊才做得完」的事**：安裝、登入、建立 repo、第一次請 Copilot 做網頁、第一次提交與同步。這些步驟最容易卡住，需要教師與助教現場協助。
2. **能自己照文件完成的事改成課後作業**：互動網頁操作與小測驗、Copilot 修改網頁、Netlify 上線（若課堂來不及）、雙重驗證、學生方案申請、學習歷程檔案。
3. **今天的最低完成線**：學生的 `index.html` 已經**提交並同步到 GitHub**。只要做到這一步，其餘都能在家照 [課後作業](homework.md) 完成。

## 4. 網頁版備案：桌機無法安裝 VS Code 或 Git 時

全部在瀏覽器完成，不需要安裝任何軟體；回家後再用 VS Code clone 下來，之後的流程不受影響。

1. 學生申請 GitHub 帳號，建立 repo（README 步驟 9）。
2. 用網頁版 AI（Copilot 網頁版 <https://github.com/copilot>，或 [提示詞](prompts.md) 中列的其他網頁版 AI）產生 `index.html` 的程式碼。
3. 在 GitHub repo 頁面按 **Add file → Create new file**，檔名輸入 `index.html`，貼上程式碼，按 **Commit changes**。
4. 有時間再做 Netlify（README 步驟 22–23），完全在瀏覽器進行。

此備案下，Copilot 的 Agent 模式、VS Code 原始檔控制改在課後作業 A1 於自己電腦完成。

| 到 1:35 仍有學生沒完成 clone | 請該生先停在原處，課後依 [homework.md](homework.md) 的 A1 從斷點接續。不要為了等少數人延後全班進度 |
| Copilot 啟用失敗或沒有回應 | 先用 [提示詞](prompts.md) 中「沒有 Copilot 時的備案」（網頁版 AI＋貼上存檔），讓學生至少完成 `index.html` 與提交、同步 |
| Netlify 來不及做 | 正常。課後作業 A2 有完整步驟，約 15 分鐘 |
