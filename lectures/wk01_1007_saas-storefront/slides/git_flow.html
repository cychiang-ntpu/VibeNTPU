Git 版本控制流程模擬器

Git 幫你把網站的每一次修改存成「版本」，就像文件的存檔點，隨時可以回到以前的樣子。這一頁讓你不用真的動檔案，就能練習 VS Code 裡「改檔案 → 存版本 → 上傳到 GitHub → 網站自動更新」的整個流程。

進階說明（選讀）

Git 是分散式版本控制系統（distributed version control system）：每位開發者的電腦都保有完整的版本歷史，並透過遠端儲存庫（remote repository，本課程使用 GitHub）交換變更。本頁模擬 VS Code「原始檔控制」面板的操作，呈現檔案如何從工作區經暫存區成為本機提交（commit），再推送至 GitHub，並觸發 Netlify 自動部署。

怎麼使用這一頁

  1. 在「1. 流程模擬器」照著黃色框的「下一步請按」提示操作：修改 → Stage → Commit → Sync。
  2. 按完 Sync 後，看最右邊（手機在最下面）的「5. Netlify 網站」自動更新。
  3. 想多練習：按「模擬：隊友在 GitHub 網頁上修改 README」再按 Pull；或點一個舊版本試試「還原」。
  4. 點「2. VS Code 介面與資料模型」對照真正的 VS Code 畫面，最後做「3. 測驗」。

請照上面黃色框的提示，從「請 Copilot 修改」開始。

1. 工作區 Working Tree

就是你電腦裡的專案資料夾，所有修改都先發生在這裡。

進階說明（選讀）

本機專案資料夾中的實際檔案。所有編輯都先發生在這裡，Git 會比對它與最近一次提交的差異。

2. 暫存區 Staging Area

準備存檔的清單：先把想存的修改放進來，再一起存成一個版本。

進階說明（選讀）

又稱索引（index），用來挑選「下一次提交要包含哪些變更」，讓一次提交只記錄一件相關的修改。

3. 本機儲存庫 Local Repository

你電腦裡存好的每一個版本；點任一版本可以查看或還原。

進階說明（選讀）

提交歷史。每個 commit 以雜湊值（hash）識別，並記錄其父提交（parent），串成一條版本鏈。點選任一提交可檢視內容。origin/main 標示本機所知的遠端最新位置（remote-tracking branch）。

    4. 遠端儲存庫 GitHub

    放在網路上的版本備份，也是和隊友共用的地方。

    進階說明（選讀）

    託管於 GitHub 的遠端儲存庫（remote，預設名稱 origin），作為團隊共用的版本來源。收到新提交時，會以 webhook 通知 Netlify。

      5. Netlify 網站

      你真正上線的網站；GitHub 一有新版本，它就自動更新。

      進階說明（選讀）

      與 GitHub repo 連結的託管服務。偵測到新提交後自動建置並部署，即持續部署（CD）。

      收到通知，部署中…
      更新完成：你沒有動 Netlify，網站就自動換成最新版本了（自動部署）。

      檢視提交

      左邊是這個版本當時的樣子。按「還原成這一版」會新增一個版本，把網站改回這個樣子，以前的版本都會留著。

      進階說明（選讀）

      檢視（checkout）：將工作區暫時切換到該提交的內容，檢視後可回到最新狀態。
      還原（revert）：不刪除任何既有提交，而是新增一個提交來抵銷之後的變更，使內容回到該版本。由於歷史保持完整，已推送到 GitHub 的提交也能安全還原，這是團隊協作時的建議做法。

      練習順序：修改 → Stage → Commit → Sync，看最右邊的網站自動更新。接著可以試試「隊友修改 README → Pull」，以及點一個舊版本「還原」。

      2.1 Git 的資料模型

      Git 把每一次存檔記成一個「提交（commit）」，一個接一個串起來，所以隨時可以看到或回到任何一個舊版本。

      進階說明（選讀）
      提交 commit
      專案在某一時間點的完整快照（snapshot），連同作者、時間、提交訊息，以及父提交（parent）的識別碼。除第一個提交外，每個提交都指向其父提交，因此歷史形成一條可回溯的鏈。
      雜湊值 hash
      Git 依提交內容（含父提交）計算出的 40 位十六進位識別碼（傳統為 SHA-1），介面通常只顯示前 7 碼。內容只要有任何改變，雜湊值就不同，因此可用來確認歷史未被竄改。
      分支 branch
      指向某個提交的可移動指標。新增提交時，目前分支（例如 main）會前進到新提交。
      遠端 remote
      另一份儲存庫的位址，clone 時預設命名為 origin，本課程即為 GitHub 上的 repo。
      遠端追蹤分支
      如 origin/main，記錄「上次與遠端通訊時，遠端 main 的位置」。它只在 fetch、pull、push 時更新；VS Code 顯示的 ↑（ahead）與 ↓（behind）即為本機 main 與 origin/main 相差的提交數。
      Sync
      VS Code 的「同步變更」依序執行 pull（取回並合併遠端提交）與 push（上傳本機提交）。若兩邊修改同一段內容，會產生合併衝突（merge conflict），需人工決定保留哪個版本。

      2.2 VS Code 按鈕與 Git 指令對照

      不需背誦指令；了解 VS Code 的按鈕在背後執行哪些指令，有助於閱讀錯誤訊息與官方文件。

      VS Code 按鈕對應指令作用
      Clone 複製存放庫git clone 網址下載遠端儲存庫的完整歷史，並設定 origin
      ＋ Stage 暫存git add 檔案將檔案目前的內容加入暫存區
      Commitgit commit -m "訊息"以暫存區內容建立新提交
      Sync（同步變更）git pull 後 git push先取回遠端提交，再上傳本機提交
      Pullgit pullfetch 遠端提交並合併至目前分支
      Timeline / 歷史git log列出提交歷史
