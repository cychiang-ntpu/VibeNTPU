# GitHub Copilot 提示設計指南（第 1 週）

> 本文件說明如何撰寫有效的提示（prompt）、如何驗證 AI 產出，以及使用 AI 生成程式碼時應注意的限制與課程規範，並附本週使用的提示範本。
> 不想逐欄替換範本內容者，可使用 [提示產生器](slides/prompt_builder.html)。

[← 回第 1 週講義](README.md)

---

## 學習目標

1. **說明**一份完整提示應包含的五項要素，以及每項要素對輸出品質的影響。
2. **解釋**「單一檔案、不使用框架、不引用外部圖片」等技術限制存在的理由。
3. **運用**迭代修改的方式，逐步讓 AI 產出符合需求。
4. **執行**接受 AI 變更前後的驗證步驟，並辨識 AI 生成程式碼的常見風險。

---

## 1. 使用方式

1. 在 VS Code 左側開啟**你 clone 下來的 repo 資料夾**（視窗標題與檔案總管上方應顯示 repo 名稱）。
2. 開啟 Copilot Chat：`Ctrl+Alt+I`（macOS：`⌃⌘I`），或點選視窗上方的 Copilot 圖示。
3. 選擇模式：
   - **Ask**：只回答問題，不修改檔案。適合發想、請 AI 解釋程式碼或錯誤訊息。
   - **Agent**：會讀取工作區、規劃步驟並建立或修改檔案。適合產生與修改網頁。
4. 複製範本，將 `【】` 內的文字換成自己的內容後送出。
5. 檢視 Copilot 提出的變更，依第 3 節的清單確認後，按 **Keep** 保留或 **Undo** 還原。

## 2. 提示規格的原則

大型語言模型依據輸入的文字預測最可能的輸出。提示越模糊，模型就越依賴「最常見的平均答案」；提示越具體，輸出越接近你真正的需求。可以把提示視為一份給外包工程師的**需求規格書**。

### 2.1 五項要素

| 要素 | 作用 | 範例 |
| --- | --- | --- |
| 角色（Role） | 設定專業標準與用語風格 | 「你是一位重視無障礙設計的前端工程師」 |
| 情境（Context） | 說明產品、目標使用者與期望的感受 | 「產品是北大學生的租屋評價平台，使用者多以手機瀏覽」 |
| 限制（Constraints） | 排除你無法處理或不符合部署環境的做法 | 「所有程式碼寫在單一 `index.html`，不使用任何框架」 |
| 驗收標準（Acceptance criteria） | 定義「完成」的可檢查條件 | 「在 375px 寬度下沒有水平捲軸；所有圖片有替代文字」 |
| 輸出格式（Output format） | 指定交付物與回報方式 | 「完成後列出新增的區塊，並說明如何預覽；不要執行 git 指令」 |

### 2.2 為什麼需要這些技術限制

本週範本中的每一項限制都有明確理由：

- **單一 `index.html` 檔案**：Netlify 在不設定建置指令時，會直接發布 repo 根目錄；`index.html` 是網站根網址預設載入的檔案。單一檔案也讓你在檢視差異、除錯與請 AI 修改時，範圍清楚可控。
- **不使用框架（React、Vue 等）**：框架通常需要 Node.js 環境、套件安裝與建置步驟，會引入本課程不處理的工具鏈與錯誤來源；純 HTML、CSS、JavaScript 可以直接由瀏覽器執行。
- **不引用外部圖片檔**：AI 常會引用不存在的圖片路徑或網址（導致破圖），或使用授權不明的圖片。以**內嵌 SVG** 繪製圖示，可確保檔案自足、清晰且可縮放。
- **不使用 emoji 作為圖示**：emoji 在不同作業系統上的外觀不一致，螢幕報讀軟體會逐字念出其名稱，也較不符合正式產品的視覺風格。
- **不執行 git 指令**：Commit 與 Sync 是本課程要求你親自掌握的技能；交由 AI 執行，可能在你不清楚的情況下改變 repo 狀態。

### 2.3 迭代修改

第一次產出通常不會完全符合需求。有效的迭代方式：

1. **一次處理一組相關修改**：將兩到三項相關要求合併在一次提示中，既能節省免費方案的使用額度，也避免多次修改互相干擾。
2. **明確說明範圍**：例如「只修改價格方案區塊，其他部分維持不變」，避免 AI 重寫整個檔案。
3. **描述觀察到的問題，而非只說「不好看」**：例如「手機寬度下導覽列的選單項目換行並遮住標題」。
4. **提供視覺證據**：可將截圖（Windows：`Win+Shift+S`；macOS：`⌘⇧4`）貼入 Copilot Chat。
5. **每得到一個滿意的版本就 Commit 一次**：commit 是你的復原點，之後的修改若出錯，可以比較差異或回到此版本。

### 2.4 以 `#` 指定檔案

在 Copilot Chat 中輸入 `#index.html`，可明確指定 Copilot 要讀取與修改的檔案，降低它修改到其他檔案的機率。

## 3. AI 輸出的驗證清單

接受變更之前與之後，請依序確認：

**按下 Keep 之前**

- [ ] 閱讀差異（diff）：變更是否只發生在預期的檔案（本週應只有 `index.html`）？
- [ ] 若 Copilot 提議執行終端機指令，一律選擇略過（Skip）。
- [ ] 回覆中是否提到你沒有要求的變更，例如刪除區塊、新增外部資源？

**按下 Keep 之後**

- [ ] 以 **Show Preview** 或瀏覽器開啟頁面，確認每個區塊都正常顯示。
- [ ] 以手機寬度檢查：瀏覽器開發者工具（`F12`，macOS：`⌥⌘I`）的裝置模式，選擇約 375px 寬度，確認沒有水平捲軸、文字未被截斷、按鈕可點擊。
- [ ] 開啟開發者工具的 **Console** 分頁，確認沒有紅色錯誤訊息。
- [ ] 點擊每一個按鈕與連結，確認行為符合預期。
- [ ] 檢查文案：產品名稱、價格與功能描述是否正確？虛構的使用者回饋或數據是否已標示為示意？
- [ ] 確認頁面中沒有個人資料、密碼或金鑰。

## 4. AI 生成程式碼的限制與課程使用規範

### 4.1 常見限制

| 限制 | 說明 | 因應方式 |
| --- | --- | --- |
| 幻覺（hallucination） | 產生看似合理但不存在的網址、套件、API，或錯誤的事實陳述 | 實際測試每個功能；事實與數據查證原始來源 |
| 無障礙（accessibility） | 常缺少圖片替代文字、顏色對比不足、未使用語意化標籤 | 在提示中明確要求，並以驗收標準檢查 |
| 資訊安全 | 可能將資料寫入公開位置、在前端存放敏感資訊，或使用不安全的寫法 | 不在前端放置任何密碼或金鑰；不理解的程式碼請 AI 以 Ask 模式解釋 |
| 授權與著作權 | 產出可能與既有程式碼相似；引用的圖片、字型可能有授權限制 | 避免外部素材；使用有明確授權的資源並註明來源 |
| 過度依賴 | 未理解就接受，導致無法除錯、無法說明自己的作品 | 要求自己能說明每個主要區塊的作用 |
| 一致性 | 同一提示每次產出不同，修改時可能改動未要求的部分 | 明確限定修改範圍；以 commit 保存可用版本 |

### 4.2 課程 AI 使用規範（摘要）

完整規範見 [課程計畫](../../docs/course_plan.md)，重點如下：

1. **揭露**：在學習歷程檔案的「AI 使用紀錄」記錄使用的工具、用途、主要提示與自己所做的修改。
2. **驗證**：AI 產生的程式碼須實際預覽與測試；發表時應能說明各主要區塊的作用。
3. **隱私**：不得將他人個人資料、密碼、存取權杖貼入 AI 對話或程式碼。
4. **誠信**：Commit 與 Sync 須自行操作；反思與市場驗證觀察須由本人撰寫；示範用的虛構資料須明確標示。

## 5. 提示範本

### 5.1 提示 0：創業題目發想（Ask 模式）

```text
我是一位大學生，正在修習一門創業通識課程。
請提出 5 個以「大學生」為目標客群的 SaaS（以訂閱或免費增值方式營運的網路服務）創業點子。

每個點子請依下列格式說明：
- 產品名稱（簡短、容易記憶）
- 一句話價值主張
- 解決的具體痛點，以及目前使用者如何處理這個問題
- 可能的收費方式（例如免費增值、月訂閱、交易抽成）
- 最大的風險或不確定性

我感興趣的領域是：【例如：租屋、二手交易、飲食、運動、社區活動】
```

### 5.2 提示 1：產生產品形象首頁（Agent 模式）

```text
你是一位資深前端工程師兼 UI 設計師，重視行動裝置體驗與無障礙設計。
請在目前工作區的根目錄建立 index.html，作為 SaaS 新創產品的形象首頁（landing page）。

【產品資訊】
- 產品名稱：【例如：三峽租屋雷達】
- 一句話介紹：【例如：北大學生專屬的租屋評價平台，協助同學在簽約前掌握真實資訊】
- 目標使用者：【例如：國立臺北大學的學生】
- 三項核心功能：【例如：1. 租屋評價 2. 契約條款提醒 3. 室友媒合】
- 收費方式：【例如：基本功能免費，進階會員每月 49 元】
- 視覺風格：【例如：清爽、可信賴，主色為青綠色】

【技術限制】
1. 所有 HTML、CSS、JavaScript 寫在同一個 index.html 檔案中，不建立其他檔案。
2. 不使用任何需要安裝或建置的框架（例如 React、Vue），只使用原生 HTML、CSS、JavaScript。
3. 不引用任何外部圖片或外部資源；圖示一律以內嵌 SVG 繪製，不使用 emoji。
4. 支援行動裝置（響應式設計），包含 <meta charset="UTF-8"> 與 viewport 設定。
5. 使用繁體中文，並使用語意化標籤（header、nav、main、section、footer）。

【頁面區塊】
1. 導覽列（產品名稱與選單）
2. 主視覺（標題、副標題、行動呼籲按鈕，例如「加入候補名單」）
3. 痛點說明（目標使用者目前遇到的問題）
4. 功能介紹（三項核心功能，以卡片呈現）
5. 價格方案（免費版與進階版比較）
6. 常見問題
7. 頁尾（版權聲明）

【驗收標準】
- 在 375px 寬度下沒有水平捲軸，導覽列在手機上可正常使用。
- 文字與背景的顏色對比足以清楚閱讀；所有 SVG 圖示有適當的替代說明或標示為裝飾。
- 瀏覽器 Console 沒有錯誤訊息。
- 若包含虛構的使用者回饋或數據，須標示為「示意」。

【輸出要求】
完成後請簡要列出頁面包含的區塊，並說明如何在 VS Code 預覽。
請不要執行任何 git 指令或終端機指令，我會自行使用原始檔控制面板提交。
```

Copilot 完成後，依第 3 節檢視差異並按 **Keep**，再於 `index.html` 上按右鍵選擇 **Show Preview**。此檔案即 SaaS 架構中的**前端**：使用者直接看到並互動的部分。

### 5.3 提示 2：迭代修改（Agent 模式）

每則提示皆明確限定修改範圍：

```text
請將 #index.html 的主色調改為【低彩度的藍灰色】，整體風格調整為【沉穩、專業】。只調整顏色相關的 CSS，其他部分維持不變。
```

```text
請在 #index.html 的主視覺標題加入淡入效果，並尊重使用者的「減少動態效果」設定（prefers-reduced-motion）。其他部分維持不變。
```

```text
請在 #index.html 的功能介紹與價格方案之間，新增「使用者回饋」區塊，放三則示意回饋，並在區塊中明確標示「以下為示意內容」。
```

```text
#index.html 在手機寬度下，導覽列的選單項目換行並遮住標題。請改為手機上顯示可展開的選單按鈕，並確保按鈕可用鍵盤操作。
```

```text
請只修改 #index.html 的價格方案區塊，改為三個方案：免費、學生（每月 49 元）、團體（每月 199 元），並標示最推薦的方案。其他部分維持不變。
```

每得到一個滿意的版本，就在原始檔控制面板 Commit 一次，訊息寫明修改內容，例如 `調整主色為藍灰色`。

### 5.4 疑難排解提示

```text
我用 Show Preview 開啟 #index.html，觀察到【畫面空白／版面錯亂／按鈕沒有反應】。
請說明可能的原因，並直接修正檔案；修正後請列出你改了哪些地方。
```

```text
（Ask 模式）請以非資訊背景大學生能理解的方式，逐一說明 #index.html 各區塊的作用，以及 CSS 如何讓版面在手機上調整。
```

```text
（Ask 模式）我在 VS Code 原始檔控制面板按下提交時，出現以下訊息：【貼上完整錯誤訊息】。請說明原因與逐步處理方式。
```

## 6. 備案：使用網頁版 AI

若 Copilot 額度用完或帳號設定有問題，仍可用網頁版 AI 完成本週任務：

1. 開啟網頁版 AI（[Claude](https://claude.ai/)、[ChatGPT](https://chatgpt.com/) 或 [Gemini](https://gemini.google.com/)），將提示 1 的開頭改為「請提供完整的 index.html 程式碼」，並刪除「在工作區建立檔案」與「不要執行 git 指令」等 Copilot 專用的句子。（[提示產生器](slides/prompt_builder.html) 選擇這些工具時會自動調整。）
2. 在 VS Code 的 repo 資料夾中點選**新增檔案**，命名為 `index.html`。
3. 將 AI 提供的程式碼**完整**貼入，按 `Ctrl+S`（macOS：`⌘S`）存檔。
4. 依第 3 節的清單驗證後，一樣以**原始檔控制**面板 Commit 並 Sync。

網頁版 AI 看不到你的工作區，修改時需將目前的程式碼或相關片段貼給它，並要求它提供完整的修改後檔案，以免遺漏部分內容。
