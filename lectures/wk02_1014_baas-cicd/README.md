## 今天會做出什麼

上完這兩個小時，你上週做好的網站會多出三樣東西：

1. **早鳥候補名單表單**：訪客填寫姓名和 Email，資料會存進 Netlify 後台，你可以登入查看。
2. **會員歡迎畫面**：訪客送出後，畫面變成「歡迎回來，〔姓名〕」；重新整理也不會消失。
3. **自動更新**：你在 VS Code 改完、按兩個按鈕，手機上的網站就自動換成新版，不需要登入 Netlify 做任何事。

最後，你會用一分鐘向鄰組介紹你的產品。

## 開始前確認（上課前或上課一開始完成）

**1. 上週的網站能開**

1. 用手機打開你上週的 Netlify 網址（長得像 `https://你的名字.netlify.app`）。

**完成後你應該看到：** 上週做好的產品首頁。

**如果不一樣：** 網站打不開或還沒部署 → 先依 [第 1 週步驟卡](../wk01_1007_saas-storefront/steps.md) 補做檢核點 2、3，或舉手請助教協助。

**2. VS Code 打開 repo 資料夾**

repo（儲存庫）＝放在 GitHub 上的專案資料夾，上週你已經把它複製（Clone）到自己電腦。

1. 打開 VS Code。
2. 點選上方選單 **檔案（File）** → **開啟最近使用的項目（Open Recent）**。
3. 點選上週的 repo 資料夾名稱。

**完成後你應該看到：** 左側檔案總管中有 `index.html`。

**如果不一樣：** 清單裡找不到 → 點選 **檔案（File）** → **開啟資料夾（Open Folder）**，找到上週 Clone 的資料夾（常見位置是「文件」底下）。

**3. 先按一次同步變更**

1. 點選 VS Code 左側最左邊那一排圖示中，形狀像樹枝分岔的圖示（**原始檔控制，Source Control**）。
2. 按下 **同步變更（Sync Changes）** 按鈕。沒有這個按鈕、只看到打勾或「沒有變更」，代表已經是最新的，可略過。

**完成後你應該看到：** 面板中沒有待處理的變更，也沒有錯誤訊息。

**如果不一樣：** 跳出要求登入 GitHub 的視窗 → 按 **允許（Allow）** 並登入。其他錯誤見 [疑難排解手冊](../../docs/tutorials/error_guide.md) Q1–Q10。

## Part 0：回顧上週（0:00–0:05，5 分鐘）

先用五分鐘把上週的內容想起來。不看筆記，想不起來也沒關係，想的過程本身就有幫助。

### 步驟 0-1：和搭檔回答三個問題（約 5 分鐘）

1. 打開 [學習單](worksheet.md) 第 1 題。
2. 和搭檔討論並寫下：
   - 上週的網站用了哪三個工具？（提示：寫網頁、存檔案、放上網路）
   - 網站上如果有人按「報名」，資料會送到哪裡？
3. 聽老師公布答案。

**完成後你應該看到：** 你寫下了 VS Code＋Copilot（寫網頁）、GitHub（存檔案）、Netlify（放上網路）。第二題的答案是：「哪裡都沒去」，這就是今天要解決的問題。

## Part 1：資料去哪了（0:05–0:20，15 分鐘）

用一個互動網頁看清楚：沒有後端時，表單資料會直接消失；加上後端服務，資料才會被保存。

### 步驟 1-1：看「沒有後端」的情況（約 5 分鐘）

1. 用瀏覽器打開 [slides/data_flow.html](slides/data_flow.html)。
2. 確認上方選的是第一個分頁 **1. 表單資料的去向**。
3. 按下 **沒有後端** 按鈕。
4. 在畫面中的模擬手機填入姓名和 Email，按 **送出**。
5. 按 **重新整理網頁**。

**完成後你應該看到：** 右邊的「Netlify 後台 Forms」是空的；重新整理後，剛剛填的資料不見了。

### 步驟 1-2：看「使用 BaaS」的情況（約 5 分鐘）

BaaS（後端即服務）＝別人幫你架好的後端，你只要設定就能用。今天用的是 Netlify Forms。

1. 按下 **使用 BaaS（`data-netlify="true"`）** 按鈕。
2. 再填一次表單，按 **送出**。
3. 按 **重新整理網頁**。
4. 按 **換一台裝置**。

**完成後你應該看到：** 右邊的「Netlify 後台 Forms」出現一筆資料；重新整理、換裝置之後，後台的資料都還在。

### 步驟 1-3：為什麼要先做早鳥名單（約 5 分鐘）

MVP（最小可行產品）＝用最少的功夫做出來、能拿去問市場「有沒有人要」的產品。與其花幾個月把整個系統做完才發現沒人用，不如先做一頁介紹加上一張報名表，看看有多少人願意留下 Email。這張報名表就是「早鳥名單」：留下資料的人越多，越代表這個需求是真的。要注意，同學互填只能證明表單能用，不能代表市場需求。

1. 在 [學習單](worksheet.md) 第 2 題寫下一句話：「我希望在＿＿天內，有＿＿位〔目標使用者〕留下 Email。」

**完成後你應該看到：** 你有一個具體的目標數字，之後可以用後台的名單來對照。

**這一步在架構中的位置：** 前端（你的網頁）負責讓人填資料，後端（Netlify Forms）負責把資料存起來。接下來就要把兩者接起來。

## Part 2：Netlify Forms 候補名單（0:20–1:00，40 分鐘）→ 檢核點 4

這一段請 Copilot 在網頁加上一張報名表，然後在 Netlify 打開收表單的功能。做完後，任何人填寫表單，你都能在 Netlify 後台看到。

### 步驟 2-1：準備提示詞（約 3 分鐘）

提示詞＝你寫給 Copilot 的文字指令。

1. 打開 [提示詞產生器](../wk01_1007_saas-storefront/slides/prompt_builder.html)。
2. 按上方的 **第 2 週：加入早鳥名單表單** 按鈕。
3. 依畫面填入你的產品名稱等資料，按下複製。

   不想用產生器也可以：打開 [prompts.md](prompts.md)，複製「提示詞 1」整個灰色框裡的文字。

**完成後你應該看到：** 提示詞已複製，內容開頭有 `#index.html`。

### 步驟 2-2：請 Copilot 修改網頁（約 5 分鐘）

1. 在 VS Code 右上方點選 Copilot 圖示，打開 **Copilot Chat** 面板。
2. 在輸入框下方的模式選單中，選擇 **Agent**。
3. 在輸入框貼上提示詞（`Ctrl+V`，Mac：`⌘V`）。
4. 按 `Enter` 送出。
5. 等待 Copilot 修改完成（約 30 秒到 2 分鐘）。

**完成後你應該看到：** `index.html` 中出現綠色（新增）和紅色（刪除）的標示，Chat 面板出現 **保留（Keep）** 和 **復原（Undo）** 按鈕。

**如果不一樣：** Copilot 只在對話中貼出程式碼、沒有修改檔案 → 確認模式是 **Agent**，而不是 **Ask**，再送出一次。

### 步驟 2-3：保留修改並檢查（約 5 分鐘）

1. 按下 **保留（Keep）**。
2. 按 `Ctrl+S`（Mac：`⌘S`）存檔。
3. 在 `index.html` 裡按 `Ctrl+F`（Mac：`⌘F`）打開搜尋框。
4. 輸入 `data-netlify`。
5. 再搜尋 `form-name`。

**完成後你應該看到：** 兩個搜尋都至少找到 1 筆。

**如果不一樣：** 找不到 → 在 Copilot Chat 輸入：`請檢查 #index.html 的表單，加上 data-netlify="true" 和隱藏的 form-name 欄位`，再按一次 **保留（Keep）**。也可以把 `index.html` 交給 [網站自我檢核工具](../../tools/vibe_check.html) 檢查 Level 2。

### 步驟 2-4：在 Netlify 打開表單偵測（約 3 分鐘）

Netlify 預設不會收表單：2023 年 4 月之後新建的網站，這個功能預設是關閉的，必須手動打開一次。這是最常被忘記的步驟。

1. 打開 <https://app.netlify.com/> 並登入。
2. 點選你的網站（專案）名稱。
3. 點選左側選單的 **Forms**。
4. 按下 **Enable form detection**。

**完成後你應該看到：** 頁面顯示表單偵測已啟用（Form detection is enabled），並提示下一次部署後會開始偵測。

**如果不一樣：** 找不到按鈕 → 點選左側 **Project configuration** → **Forms** → **Form detection**，在那裡打開。

### 步驟 2-5：提交並同步（約 3 分鐘）

提交（Commit）＝替這次修改存一個版本並寫說明；同步（Sync）＝把新版本送到 GitHub。

1. 點選 VS Code 左側的 **原始檔控制（Source Control）** 圖示（樹枝分岔的形狀）。
2. 在上方的訊息欄輸入 `新增早鳥名單表單`。
3. 按下 **提交（Commit）**。
4. 按下 **同步變更（Sync Changes）**。

**完成後你應該看到：** 原始檔控制面板變回空的，沒有待處理的變更。

**如果不一樣：** 按 Commit 時跳出「沒有暫存的變更」→ 按 **是（Yes）**。

### 步驟 2-6：等 Netlify 部署完成（約 2 分鐘）

1. 回到 Netlify，點選左側選單的 **Deploys**。
2. 看最上面那一筆，等它的狀態變成 **Published**。

**完成後你應該看到：** 最上面那一筆顯示 `新增早鳥名單表單` 和 **Published**。

**如果不一樣：** 你是先 Sync 之後才打開表單偵測 → 按右上方 **Trigger deploy** → **Deploy site**，重新部署一次。狀態顯示 **Failed** → 見 [疑難排解手冊](../../docs/tutorials/error_guide.md) Q11–Q13。

### 步驟 2-7：自己填一次表單（約 3 分鐘）

1. 用瀏覽器打開你的 `https://…netlify.app` 網址。不要直接雙擊電腦裡的 `index.html`（網址會是 `file:///…`，那樣的資料不會送到 Netlify）。
2. 捲動到早鳥名單表單。
3. 填入你的姓名和 Email。
4. 按下送出按鈕。

**完成後你應該看到：** 一個「感謝」或「已送出」的畫面。

### 步驟 2-8：請 3 位同學填寫（約 8 分鐘）

1. 把你的網址傳給旁邊 3 位同學（可以用 QR code 或課程群組）。
2. 請他們用手機填寫你的表單。
3. 同時，你也幫他們填寫。

**完成後你應該看到：** 同學跟你說「送出了」。

### 步驟 2-9：查看後台名單（約 3 分鐘）

1. 回到 Netlify，點選左側選單的 **Forms**。
2. 在表單清單中點選 **waitlist**。

**完成後你應該看到：** 至少 3 筆資料，每筆有姓名、Email 和送出時間。**檢核點 4 完成。**

**如果不一樣：** 看不到 `waitlist` 或沒有資料 → 見 [疑難排解手冊](../../docs/tutorials/error_guide.md) Q14–Q16，或看 [Netlify Forms 步驟教學](../../docs/tutorials/netlify_forms.md)。

**這一步在架構中的位置：** 你剛剛把前端的表單接上了 BaaS（Netlify Forms），網站第一次有了「會保存資料的後端」。

請交換駕駛與導航員。

## Part 3：LocalStorage 會員畫面（1:00–1:35，35 分鐘）→ 檢核點 5

這一段讓訪客送出表單後，畫面變成「歡迎回來，〔姓名〕」，而且重新整理也會記得他。記住名字的地方叫 LocalStorage。

LocalStorage（本機儲存）＝瀏覽器在這台裝置上替網站保留的小筆記本。只有這台裝置、這個瀏覽器看得到，換手機就沒有了。

### 步驟 3-1：先在互動網頁看差異（約 5 分鐘）

1. 回到 [slides/data_flow.html](slides/data_flow.html) 分頁 **1. 表單資料的去向**，選 **使用 BaaS**。
2. 填表並按 **送出**，看到歡迎畫面。
3. 按 **重新整理網頁**。
4. 按 **換一台裝置**。
5. 按 **登出**。

**完成後你應該看到：** 重新整理後歡迎畫面還在；換裝置後歡迎畫面不見了，但後台的資料還在；登出後回到表單。

### 步驟 3-2：請 Copilot 做會員畫面（約 8 分鐘）

1. 打開 [prompts.md](prompts.md)，複製「提示詞 2」整個灰色框裡的文字。
2. 回到 VS Code 的 Copilot Chat（保持 **Agent** 模式，可以接在剛剛的對話裡）。
3. 貼上提示詞，按 `Enter` 送出。
4. 等待修改完成。
5. 按下 **保留（Keep）**，再按 `Ctrl+S`（Mac：`⌘S`）存檔。

**完成後你應該看到：** `index.html` 中多了一段 `<script>` 程式，裡面有 `localStorage` 字樣（可用 `Ctrl+F` 搜尋）。

### 步驟 3-3：提交並同步（約 3 分鐘）

1. 點選左側的 **原始檔控制（Source Control）** 圖示。
2. 在訊息欄輸入 `新增會員畫面`。
3. 按下 **提交（Commit）**。
4. 按下 **同步變更（Sync Changes）**。
5. 到 Netlify 的 **Deploys**，等最上面一筆變成 **Published**。

**完成後你應該看到：** Deploys 最上面一筆顯示 `新增會員畫面` 和 **Published**。

### 步驟 3-4：用手機測試（約 8 分鐘）

1. 用手機打開你的 `https://…netlify.app` 網址。
2. 填寫表單並送出。
3. 確認畫面變成「歡迎回來，〔你的名字〕」。
4. 在手機上重新整理網頁。
5. 按下 **登出**。

**完成後你應該看到：** 重新整理後歡迎畫面還在；按登出後回到表單。回到 Netlify 的 **Forms → waitlist**，也看得到剛剛這一筆。

**如果不一樣：** 送出後沒有變成歡迎畫面 → 見 [疑難排解手冊](../../docs/tutorials/error_guide.md) Q17–Q18。手機顯示舊版 → 往下拉重新整理，或用無痕視窗打開。

### 步驟 3-5（選做）：親眼看到存了什麼（約 5 分鐘）

1. 用電腦的 Chrome 或 Edge 打開你的網址，送出一次表單。
2. 按 `F12`（Mac：`⌘⌥I`）打開開發者工具。
3. 點選上方的 **Application**（應用程式）分頁。
4. 在左側點開 **Local storage**，再點選你的網址。

**完成後你應該看到：** 一個項目，值是你剛剛輸入的名字。只存名字，沒有 Email。詳細操作見 [LocalStorage 步驟教學](../../docs/tutorials/localstorage.md)。

### 步驟 3-6：自我檢核（約 3 分鐘）

1. 打開 [網站自我檢核工具](../../tools/vibe_check.html)。
2. 依畫面指示放入你的 `index.html`，查看 Level 3。

**完成後你應該看到：** Level 3 通過。**檢核點 5 完成。**

提醒：這只是「模擬登入」，沒有密碼、也沒有真正確認身分，適合展示產品流程，不能當作真正的會員系統。

**這一步在架構中的位置：** 名單存在伺服器（Netlify），名字存在訪客自己的瀏覽器（LocalStorage）。你現在會分辨兩種存資料的地方。

請交換駕駛與導航員。

## Part 4：自動更新 CI/CD（1:35–1:50，15 分鐘）→ 檢核點 6

這一段要證明：你只要在 VS Code 提交並同步，網站就會自動更新，不用碰 Netlify。

CI/CD（持續整合／持續部署）＝程式碼一更新，系統就自動把新版放上網站的做法。

### 步驟 4-1：先猜一猜（約 1 分鐘）

1. 用手機打開你的網站，記下主按鈕現在的顏色和文字。
2. 在 [學習單](worksheet.md) 第 3 題寫下：「按完同步之後，我需不需要去 Netlify 按什麼？」

### 步驟 4-2：做一個一眼看得出來的修改（約 4 分鐘）

1. 打開 [prompts.md](prompts.md)，複製「提示詞 3」其中一個灰色框（例如把按鈕改成亮橘色）。
2. 在 Copilot Chat 貼上並送出。
3. 按下 **保留（Keep）**，再按 `Ctrl+S`（Mac：`⌘S`）存檔。

**完成後你應該看到：** `index.html` 中按鈕的顏色或文字被改掉了。

### 步驟 4-3：提交並同步（約 2 分鐘）

1. 點選左側的 **原始檔控制（Source Control）** 圖示。
2. 在訊息欄輸入 `改按鈕顏色`。
3. 按下 **提交（Commit）**。
4. 按下 **同步變更（Sync Changes）**。

### 步驟 4-4：什麼都不做，直接看手機（約 2 分鐘）

1. 不要打開 Netlify。
2. 等大約 30 秒。
3. 在手機上重新整理你的網站。

**完成後你應該看到：** 按鈕變成新的顏色或文字。**檢核點 6 完成。**

**如果不一樣：** 還是舊的 → 再等 30 秒，往下拉重新整理，或用無痕視窗打開。

### 步驟 4-5：看 Netlify 幫你做了什麼（約 3 分鐘）

1. 打開 Netlify，點選左側選單的 **Deploys**。

**完成後你應該看到：** 最上面多了一筆 `改按鈕顏色`，狀態是 **Published**。每次同步都會留下一筆紀錄。

### 步驟 4-6（選做）：回到上一版（約 3 分鐘）

1. 在 **Deploys** 清單中，點選下面一筆較舊的部署（例如 `新增會員畫面`）。
2. 按下 **Publish deploy**。
3. 用手機重新整理，確認按鈕回到舊顏色。
4. 回到 **Deploys**，點選最新那一筆，再按一次 **Publish deploy**，把網站換回新版。

**完成後你應該看到：** 網站能在幾秒內切換新舊版本。詳細說明見 [CI/CD 步驟教學](../../docs/tutorials/cicd.md)。

**這一步在架構中的位置：** GitHub 收到新版後自動通知 Netlify，Netlify 自動部署。這條自動化的路線就是 CI/CD。

## Part 5：一分鐘發表與收尾（1:50–2:00，10 分鐘）→ 檢核點 7

### 步驟 5-1：填好一分鐘講稿（約 3 分鐘）

把下面的空格填好，唸一次大約一分鐘：

> 我們的產品叫〔名稱〕，要幫〔誰〕解決〔什麼問題〕。
> 現在的網站可以讓人加入早鳥名單，目前收到〔N〕筆報名。
> 送出後會看到會員歡迎畫面，而且我們每次修改，網站都會自動更新。
> 我們希望在〔幾天〕內有〔幾位〕目標使用者報名，下一步要〔做什麼〕。

### 步驟 5-2：向鄰組發表（約 5 分鐘）

1. 兩組面對面，各用一分鐘介紹，邊講邊用手機展示網站。
2. 聽的一組實際填一次對方的表單。

**完成後你應該看到：** 對方的後台多了一筆資料。**檢核點 7 完成。**

### 步驟 5-3：收尾（約 2 分鐘）

1. 完成 [學習單](worksheet.md) 最後的出場券。
2. 在 [學習歷程檔案](../../templates/portfolio_README.md) 勾選今天完成的檢核點。
3. 檢核點 0–7 都完成的同學，可以在 [網站自我檢核工具](../../tools/vibe_check.html) 產生完課證明。
