## 2. 段落 0：暖身回想（0:00–0:05）

1. 三題回想，不看筆記；搭檔討論 1 分鐘後公布答案。說明提取練習與間隔效應的依據。
2. 由第 3 題帶出本週主題：尚缺的架構元件為 BaaS。

## 3. 段落 1：觀念建立（0:05–0:20）

3. 〔現場〕在教師第 1 週的網站按「註冊」，提問：資料送到哪裡？
4. 〔data_flow.html 分頁 1，沒有後端〕資料未被接收。
5. 前端與後端的責任對照表；強調「前端不可信任」，所有關鍵檢查需在後端進行。（3 分鐘）
6. 後端的五項工作：接收、驗證、商業邏輯、持久化、回應；自建成本表。（2 分鐘）
7. 精實創業：建構—測量—學習循環、經過驗證的學習、可否證假設（示範「不佳」與「較佳」的寫法）。（3 分鐘）
8. MVP 類型：著陸頁煙霧測試、禮賓式、綠野仙蹤式；Dropbox 示範影片案例，同時指出倖存者偏差。（2 分鐘）
9. 成功指標：不重複訪客數、轉換率、質性訊號；虛榮指標與同學樣本偏差。學生於學習單第 2 題寫下假設。（3 分鐘）
10. 〔data_flow.html 分頁 1，有 BaaS〕資料進入後台；BaaS 取捨表：速度與成本 vs. 供應商鎖定、額度、資料所有權。（2 分鐘）

## 4. 段落 2：Netlify Forms（0:20–1:00）

11. 教師完整示範：Copilot（Agent 模式）新增表單 → Keep → Enable form detection → Commit＋Sync → 填表 → 後台。（5 分鐘）
12. 機制說明：Netlify 於部署時解析 HTML、偵測 `data-netlify` 表單並建立端點；瀏覽器以 POST、urlencoded 格式送出；`form-name` 的用途。
13. 重點提醒：新網站自 2023 年 4 月起預設關閉表單偵測；開啟後需重新部署才會生效。
14. 學生實作：提示詞產生器（第 2 週模式）；確認 VS Code 已開啟 repo 資料夾、提示詞包含 `#index.html`。
15. 巡堂檢查：`name`、`method="POST"`、`data-netlify`、`form-name`；以本機 `file:///` 測試無法送達。
16. 全班互填 → 投影教師後台。說明同學資料僅證明功能運作，不代表需求。
17. 個資告知：表單應說明蒐集目的；簡述個人資料保護法第 8 條的告知事項。
18. 設定示範（選講）：Forms → Submission notifications；匯出 CSV；垃圾訊息過濾。

## 5. 段落 3：LocalStorage（1:00–1:35）

19. 〔data_flow.html 分頁 1〕送出後重新整理、換一台手機，對照伺服器端與瀏覽器端的差異。
20. 對照表：資料位置、讀取者、跨裝置、清除條件、適合用途。
21. 〔data_flow.html 分頁 2〕分類練習。
22. 〔現場〕F12 → Application → Local storage，展示實際儲存內容，並示範手動寫入一個名字即可「登入」，說明這只是介面模擬。
23. 安全性：同源範圍、僅能存字串、任何頁面腳本皆可讀取（XSS 風險）；不存密碼、權杖與個資。
24. 學生以提示詞 2 實作，並依驗證清單檢查 `response.ok`、`textContent`、只存名字。

## 6. 段落 4：持續部署（1:35–1:50）

25. 〔data_flow.html 分頁 3〕模擬一次，含回到上一版。
26. 預測：Commit＋Sync 後是否需要到 Netlify 操作？
27. 〔現場〕教師投影自己的網站，以 Copilot 修改顏色 → Commit → Sync，全班觀察自動更新；同時開啟 Netlify Deploys 頁面顯示建置紀錄。
28. 機制：GitHub 通知 Netlify → 建置 → 原子式發布；每次部署保留獨立網址，可即時回復。
29. 定義：持續整合、持續交付、持續部署的差異；本課程缺少自動化測試，GitHub Actions 自動檢核為第一步。延伸閱讀 DORA。
30. 學生自行完成一次。

31. 一分鐘 MVP 發表結構（產品、目標使用者、假設、指標、架構、目前數據、下一步）→ 兩組互相發表 → 抽 2–3 組上台。
32. 期末 Pitch 示範講稿。
33. 出場券；學習歷程檔案 3-2-1 反思。
