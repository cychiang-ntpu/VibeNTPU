    2.1 伺服器端資料（雲端資料庫、Netlify Forms）

    • 資料保存在伺服器，由服務提供者負責備份與存取控制
    • 網站擁有者可檢視所有使用者的資料
    • 與裝置無關：換手機、換電腦仍可取得（前提是能辨識使用者身分，通常需要登入系統）
    • 適用：名單、訂單、會員資料等需要集中管理的資料

    2.2 用戶端資料（LocalStorage）

    • 資料保存在使用者自己的瀏覽器，不會隨請求傳到伺服器
    • 網站擁有者無法從後台看到
    • 換一台裝置或換一個瀏覽器就讀不到；使用者清除網站資料時也會消失
    • 適用：介面偏好、「此瀏覽器已填過表單」等只與這台裝置有關的狀態

    2.3 技術細節：資料是怎麼送出與保存的

    表單送出（HTTP POST）。使用者按下送出時，瀏覽器將每個具有 name 屬性的欄位編碼為 application/x-www-form-urlencoded 格式，以 HTTP POST 請求傳給伺服器。Netlify 在部署時已辨識帶有 data-netlify="true" 的表單，因此能接收並保存這筆資料；若沒有任何後端，請求無處可去，資料即遺失。

    POST / HTTP/1.1
Host: your-site.netlify.app
Content-Type: application/x-www-form-urlencoded

form-name=waitlist&name=%E5%B0%8F%E6%98%8E&email=ming%40example.com

    LocalStorage 的範圍：同源政策。LocalStorage 依來源（origin）隔離，來源由「通訊協定＋主機名稱＋連接埠」組成，例如 https://your-site.netlify.app。不同來源的網站無法讀取彼此的資料；同一網站在另一台裝置、另一個瀏覽器，或以 file:// 開啟時，也都是各自獨立的儲存空間。

    因此，本課程以 LocalStorage「模擬」會員狀態僅作為示範：它能記住「此瀏覽器的使用者曾填過表單」，但不能證明身分。正式的會員系統需由伺服器驗證身分（例如密碼搭配工作階段 session 或權杖 token）。

    Netlify Deploys（部署紀錄）

      為什麼大型網站頻繁更新，卻不需要停機維護？
      Netlify 採用原子部署（atomic deploy）：新版本在獨立環境中完整建置，全部成功後才一次切換流量；建置期間舊版照常服務，使用者不會看到「一半新、一半舊」的網站。每次部署都保留為不可變的快照（immutable deploy），因此回復（rollback）只需將先前的部署重新發布，不必重新建置。大型平台亦以類似概念搭配藍綠部署、灰度發布（canary release）等策略降低風險。
      取捨：自動部署讓錯誤也會被自動發布，因此實務上會在部署前加入自動化測試（CI）；本課程的 GitHub Actions 自我檢核即為一例。
